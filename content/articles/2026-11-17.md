## 概要

Reactの `<ViewTransition>`コンポーネントでは、Viewport外の要素はペアにならず、アニメーションしない仕様になっているらしいです。

<br />

→ このポートフォリオサイトでは、以下のようなアニメーションを実装するために、View Transitions APIを直接呼び出す実装にしました。

## 仕様の壁あり

<br />

<br />

**Claude先生「それはReactの仕様ですね。」**

<br />

<br />

なんとびっくり。どうやらViewport外の要素はアニメーションのペアから外されているとReactの仕様で決まっているらしいです。

<br />

[Reactの公式ドキュメントより：](https://react.dev/reference/react/ViewTransition#:~:text=If%20either%20the%20mounted%20or%20unmounted%20side%20of%20a%20pair%20is%20outside%20the%20viewport%2C%20then%20no%20pair%20is%20formed.%20This%20ensures%20that%20it%20doesn%E2%80%99t%20fly%20in%20or%20out%20of%20the%20viewport%20when%20something%20is%20scrolled.%20Instead%20it%E2%80%99s%20treated%20as%20a%20regular%20enter/exit%20by%20itself)

> If either the mounted or unmounted side of a pair is outside the viewport, then no pair is formed.&#x20;

<br />

> 日本語訳： ペアのマウント側またはアンマウント側のいずれかがビューポートの外にある場合、ペアは形成されません。

<br />

ということで、私のポートフォリオでは以下の2ステップで、Viewport外からもアニメーションさせることにしました。

<br />

**1. ReactにViewTransitionのペアを作らせないようにする**

<br />

`<ViewTransition>`の`share`はtransition typeごとに指定を変えられます。ブラウザの「戻る」のときだけ`work-back-manual`というtypeを付けて、そのときは`share`を`none`にすると、戻るときだけReactは画像をペアにしなくなります。

<br />

```tsx
const WORK_IMAGE_SHARE = {
  "work-back-manual": "none", // ← 戻るときだけペアを作らない
  default: "morph",
};

<ViewTransition name={`work-image-${slug}`} share={WORK_IMAGE_SHARE}>
  {/* 作品の画像 */}
</ViewTransition>
```

<br />

**2. `view-transition-name`の名付けを自前実装**

<br />

ブラウザ標準のView Transitions APIは、名前さえ付いていれば画面外の要素もキャプチャしてくれます。

<br />

なので、詳細ページの画像に名前を付けてから`document.startViewTransition`を直接呼び、一覧が描かれたら作品一覧のタイルにも同じ名前を付けます。

<br />

```ts
hero.style.viewTransitionName = "work-back-morph"; // 詳細ページの画像に名前を付ける

const transition = document.startViewTransition(async () => {
  await goBack(); // typeを付けて一覧へ戻る
  tile.style.viewTransitionName = "work-back-morph"; // 作品一覧のタイルにも同じ名前を付ける
});

transition.finished.finally(clearNames); // 終わったら名前を外す
```

（実際のコードを簡略化しています）

<br />

なお、Reactとは別に自分で遷移を始めるので、Reactの遷移や他の操作とぶつかった時の対策として、いくつかエッジケース対応も入れています。（今回は割愛）

<br />

ということで、works詳細からスクロールして戻った時にもいい感じのTransitionが再生されるようになりました🎉

## Reactはなんでこういう仕様にしたんだろう？

仕様書の注意書きでは

> This ensures that it doesn’t fly in or out of the viewport when something is scrolled.

また、[ソースコード](https://github.com/facebook/react/blob/cbb046ab92b66dfc4ad1e1ea30d4b8beae6f2c24/packages/react-reconciler/src/ReactFiberCommitViewTransitions.js#L607-L640)上のコメントでは

> // Revert the transition names. This boundary is not in the viewport\
> // so we won't bother animating it.

<br />

などが残されています。

<br />

fly in （飛び込む）

fly out （飛び出す）

bother（煩わす）

<br />

と、なんだか要素がViewport外と往来することに対して、React側から一定のウザがりを感じてます。（そういう解釈でいいんだろうか。）

画面外から要素が飛んでくるのが悩みになる、と言っている[記事](https://dev.to/iamschulz/view-transitions-outside-the-viewport-551)もあるっぽい。

<br />

自分でも調べてみたりAIに聞いてみたりしましたが、結局React側の気持ちはよくわかりませんでした。友達に聞いてみたところ「画面外の情報をわざわざレンダリングすることに対して価値がないと思っているんじゃない？」などの考えも教えてもらいました。
